# Fase 00.6 — Handoff para Codex

Status: done (concluída em 2026-07-28)

## Objetivo

Registrar o estado real do projeto após a criação inicial com outro agente e deixar a continuidade
explícita para desenvolvimento assistido pelo Codex.

## Escopo executado

- Leitura de continuidade do PRD, índice de ADRs e roadmap de tasks.
- Comparação entre documentação e código implementado.
- Verificação de rastros do agente anterior: nenhum arquivo de projeto rastreável específico do
  opencode foi encontrado; há apenas um diretório interno em `.git/opencode`, fora do entregável.
- Atualização do README para separar estado implementado de contratos planejados.
- Inclusão de Maven Enforcer para falhar cedo quando o Maven roda com JVM diferente de Java 21.
- Remoção de Mockito do teste unitário de `HealthController`; o teste agora usa fakes simples de
  `JdbcTemplate` e não depende de auto-attach de agente no Docker/WSL.
- Criação e instalação de skills pessoais do Codex para continuidade de implementação:
  `gnomon-sdd-continuity`, `gnomon-identity-tenancy`, `gnomon-scheduling-booking` e
  `gnomon-quality-gates`.
- Registro deste checkpoint no roadmap.

## Estado real encontrado

- Fases `00` e `00.5` estão concluídas e coerentes com o código.
- Próxima fase de produto: `01` — identidade Keycloak e tenancy.
- O código implementa apenas a fundação técnica:
  - aplicação Spring Boot 4.1.0 / Java 21 / Maven;
  - módulos vazios por feature em `io.gnomon.<module>.{api,application,domain,infrastructure}`;
  - Flyway com `V1__extensions.sql`;
  - health/readiness sob `/v1/health` e `/v1/ready`;
  - segurança temporária `permitAll`;
  - Spotless, ArchUnit e smoke de integração com PostgreSQL/Testcontainers.
- Ainda não há implementação de autenticação real, tenancy, catálogo, disponibilidade, booking,
  cache Redis funcional ou observabilidade completa.

## Divergências corrigidas

- O README descrevia autenticação/multi-tenancy e observabilidade como se já estivessem
  operacionais. O texto agora identifica esses pontos como contratos das fases `01` e `06`.
- `./mvnw test` nesta WSL estava executando com Java 17 e falhava tarde com incompatibilidade de
  bytecode (`class file version 65`). O build agora exige Java 21 já na fase `validate`.
- `HealthControllerTest` dependia do mock maker inline do Mockito e falhava no container Maven/JDK
  21 por indisponibilidade de auto-attach. O teste foi simplificado para usar fakes locais.
