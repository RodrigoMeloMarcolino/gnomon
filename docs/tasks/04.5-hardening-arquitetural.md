# Fase 04.5 — Hardening arquitetural antes da fase 05

Status: done

## Objetivo

Consolidar a taxonomia `application.port.in` / `application.port.out` / `application.service`,
separar regras puras de falhas de aplicação e impedir acessos internos entre módulos, sem mudar
API, schema, migrations ou regras de booking.

## Escopo e aceite

- `*Result` é saída interna e `*Response` é exclusivamente HTTP.
- Customer global, seu port e adapter pertencem a `customers`; booking o consome por port.
- O principal autenticado pertence a `shared.security`.
- Catálogo passa a expor o snapshot agendável por input port; adapters consumidores não acessam
  seus repositories internos.
- Fingerprint SHA-256 e libphonenumber são adapters de infraestrutura; geração determinística de
  slots fica no domínio.
- Handlers usam códigos de erro de aplicação, nunca implementação de service; 422 usa
  `UNPROCESSABLE_CONTENT`.
- ArchUnit passa a proteger os limites e os testes existentes, incluindo concorrência, permanecem
  verdes.

## Validação

- [x] `./mvnw spotless:check`
- [x] `./mvnw test`
- [x] `./mvnw test -Dtest=ArchitectureTest`
- [x] `./mvnw verify -Pintegration`

## Riscos

É uma mudança estrutural ampla. Não deve ser iniciada a fase 05 até os cinco gates e a prova de
violação ArchUnit estarem verdes.

## Notas de implementação — 2026-07-29

- O catálogo passou a expor também o contexto autorizado de calendário por `CalendarUseCase`;
  availability não acessa mais repositories ou modelos internos de catalog.
- Os adapters de booking e availability usam exclusivamente o input port
  `SchedulableOfferingUseCase`; os construtores de compatibilidade que mascaravam acesso interno
  foram removidos e os testes passaram a mockar os contratos públicos.
- `ArchitectureTest` agora protege explicitamente esses adapters contra dependência em
  `catalog.application.port.out` e `catalog.domain`.
- Todos os records de contrato anteriormente declarados dentro de interfaces foram extraídos para
  arquivos públicos próprios. Commands, results e modelos de gateway permanecem separados, sem
  alterar o contrato HTTP.
- A compilação e a suíte unitária foram executadas no contêiner Maven com Java 21; os relatórios
  registram zero failures/errors. Os gates de formatação, arquitetura isolada e integração ainda
  são pendentes nesta etapa.

## Fechamento — 2026-07-29

  passou com 5 testes; a integração passou com 33 testes usando PostgreSQL 16 e Keycloak 26; o
