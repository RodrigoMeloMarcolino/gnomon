# Workstream 07.5 — Portfólio multi-tenant

Status: todo

## Objetivo

Adicionar portfólio de imagens tenant-owned, com upload direto privado, processamento assíncrono, publicação editorial e entrega pública autorizada.

## Dependências e componentes prováveis

Depende dos ADRs 0020/0021 e reserva `V6__tenant_portfolio.sql`; fase 08 passa a reservar V7. O módulo futuro é `io.gnomon.portfolio` com `api → application → domain ← infrastructure`, port de tenancy e AWS SDK limitado ao adapter S3.

Componentes: aggregate e máquina de estados, repositories JPA/ports, uso/quota, jobs/worker,
adapter S3-compatible, executor libvips, controllers/DTOs/handler, scheduler de reconciliação,
configurações e Compose/Garage.

## Entregas, testes e aceite

Seguir as doze entregas do plano. Cada uma deve registrar objetivo, componentes, dependências, testes, riscos e merge independente. A feature só fecha com Spotless, unitários, ArchUnit, integração PostgreSQL/Garage, reconciliação e smoke upload → processamento → publicação → remoção verdes.

Cobrir unidade para estados, publicação/destaque, keys, quota, idempotência, versão otimista,
retries e compensações; HTTP para status, headers, JSON, paginação, ETag, redirects e erros;
PostgreSQL para migration, constraints, quota/ordem concorrentes, claims e processamento×remoção;
e Garage para presign, HEAD, streaming, path-style, CORS, delete e indisponibilidade. Cobrir MIME
falso, bytes mágicos inválidos, animação, truncamento, excesso de pixels, EXIF, timeout e saída
parcial, além de owner/admin, staff negado, dois tenants e impossibilidade de obter source/master.

## Riscos

Quotas e armazenamento podem divergir após falha; o banco é o limite rígido e reconciliadores corrigem drift. Processamento é hostil por natureza: libvips não roda no processo web, originais não são públicos e saídas parciais são compensadas.

## Notas de implementação

Etapa atual concluída apenas documentalmente; nenhuma classe, migration, dependência ou infraestrutura foi alterada.
